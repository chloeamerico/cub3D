ÉTAPE 2 : Lecture et stockage du fichier .cub
2.1 - Ouvrir et lire le fichier

Ouvrir le fichier avec open() et lire son contenu avec get_next_line ligne par ligne. Stocker chaque ligne dans une liste chaînée ou un tableau temporaire.
​

​
2.2 - Ignorer les lignes vides

Les lignes vides entre les éléments de configuration sont autorisées. Créer une fonction qui skip les lignes vides mais détecte quand la carte commence.
​

​
2.3 - Séparer configuration et carte

Identifier où commence la carte (premier caractère 0, 1, ou N/S/E/W après les éléments de config). Tout ce qui précède = configuration, tout après = carte.
​

​
Points critiques

La carte est toujours en dernier dans le fichier. Ne pas confondre lignes vides (séparateurs) avec espaces dans la carte (caractères valides).
​

​
ÉTAPE 3 : Parser les éléments de configuration
3.1 - Créer la structure de données

Définir une structure pour stocker les informations parsées :

​

c
typedef struct s_config {
    char *north_texture;
    char *south_texture;
    char *west_texture;
    char *east_texture;
    int floor_rgb[3];
    int ceiling_rgb[3];
    int config_complete;  // flag pour vérifier que tout est parsé
} t_config;

3.2 - Parser les textures (NO, SO, WE, EA)

Pour chaque ligne de configuration :
​

​

    Identifier l'identifiant (NO, SO, WE, EA)

    Ignorer les espaces multiples entre l'identifiant et le chemin

    Extraire le chemin du fichier .xpm

    Vérifier que le fichier existe avec open() ou access()

    Stocker le chemin dans la structure

    Vérifier qu'il n'y a pas de doublon (chaque texture doit être définie une seule fois)

Exemple à parser :

​

text
NO    ./textures/north.xpm
SO ./textures/south.xpm

3.3 - Parser les couleurs (F et C)

Pour les couleurs du sol (F) et du plafond (C) :
​

​

    Identifier l'identifiant (F ou C)

    Extraire la chaîne de couleurs au format R,G,B

    Utiliser ft_split(',') pour séparer les 3 valeurs

    Convertir chaque valeur en int avec atoi()

    Vérifier que chaque valeur est dans le range 0-255

    Vérifier qu'il y a exactement 3 valeurs (ni plus, ni moins)

    Stocker dans floor_rgb[11] ou ceiling_rgb[11]

Exemple à parser :

​

text
F 220,100,0
C 225,30,0

3.4 - Validation complète de la configuration

Vérifier que les 6 éléments obligatoires sont présents :
​

​

    Les 4 textures (NO, SO, WE, EA) doivent être définies et accessibles

    Les 2 couleurs (F, C) doivent être définies avec des valeurs valides

    Aucun élément ne doit être dupliqué

    Retourner "Error\n" avec un message si un élément manque

Points critiques

L'ordre des éléments n'est pas important (sauf la carte qui est toujours en dernier). Les espaces multiples entre identifiant et valeur sont autorisés. Les fichiers de texture doivent exister avant de continuer le parsing.

​
ÉTAPE 4 : Parser et stocker la carte
4.1 - Extraire les lignes de la carte

Une fois les 6 éléments de config parsés, tout le reste du fichier est la carte. Stocker chaque ligne exactement comme elle apparaît dans le fichier (avec espaces).
​

​
4.2 - Créer le tableau 2D

Créer un tableau de chaînes de caractères (char **map) :

​

    Compter le nombre de lignes de la carte

    Trouver la longueur de la ligne la plus longue

    Allouer char **map avec le nombre de lignes

    Allouer chaque ligne individuellement

    Copier chaque ligne dans le tableau en préservant les espaces

Option : normaliser toutes les lignes à la même longueur en ajoutant des espaces à la fin.

​
4.3 - Identifier le joueur

Parcourir la carte pour trouver le caractère de départ (N, S, E, ou W) :
​

​

    Stocker la position X et Y du joueur

    Stocker l'orientation (N, S, E, W)

    Vérifier qu'il y a exactement un joueur (ni 0, ni 2+)

    Remplacer le caractère du joueur par 0 dans la carte

Exemple :

​

text
1111111
100N001
1111111

Le joueur est en position (3, 1) avec orientation Nord.
4.4 - Stocker dans la structure finale

Créer la structure de données finale :

​

c
typedef struct s_data {
    t_config config;    // éléments de configuration
    char **map;         // tableau 2D de la carte
    int map_width;      // largeur max de la carte
    int map_height;     // hauteur de la carte
    int player_x;       // position X du joueur
    int player_y;       // position Y du joueur
    char player_dir;    // direction (N/S/E/W)
} t_data;

Points critiques

Les espaces font partie de la carte et doivent être préservés. La carte peut avoir des formes irrégulières (non rectangulaires). Le joueur doit être unique.
​

​
ÉTAPE 5 : Validation de la carte
5.1 - Vérifier les caractères valides

Parcourir chaque caractère de la carte :
​

​

    Seuls 0, 1, (espace), et N/S/E/W sont autorisés

    Tout autre caractère = erreur

    Les tabulations et autres whitespaces ne sont pas autorisés (seulement les espaces)

5.2 - Vérifier les bordures

Vérifier que la première et la dernière ligne ne contiennent que des 1 et des espaces. Vérifier que chaque ligne commence et finit par un 1 (en ignorant les espaces de début/fin).

​
5.3 - Algorithme de flood fill (validation des murs)

C'est la partie la plus complexe. L'objectif est de vérifier que tous les espaces vides (0) et la position du joueur sont entourés de murs (1).
​

​

Algorithme :

​

c
void flood_fill(t_data *data, int x, int y, char **visited)
{
    // Si hors des limites de la carte = erreur (map ouverte)
    if (y < 0 || y >= data->map_height || x < 0 || x >= data->map_width)
    {
        printf("Error\nMap is not closed\n");
        exit(1);
    }
    
    // Si c'est un mur ou déjà visité, stop
    if (data->map[y][x] == '1' || visited[y][x] == 1)
        return;
    
    // Si c'est un espace (hors carte) = erreur
    if (data->map[y][x] == ' ')
    {
        printf("Error\nMap is not closed\n");
        exit(1);
    }
    
    // Marquer comme visité
    visited[y][x] = 1;
    
    // Récursion sur les 4 directions (haut, bas, gauche, droite)
    flood_fill(data, x + 1, y, visited);
    flood_fill(data, x - 1, y, visited);
    flood_fill(data, x, y + 1, visited);
    flood_fill(data, x, y - 1, visited);
}

Lancer le flood fill depuis la position du joueur. Si le flood fill atteint un espace ou sort de la carte, la carte est invalide.

​
5.4 - Gestion des espaces critiques

Un espace adjacent à un 0 rend la carte invalide. Parcourir tous les 0 et vérifier que leurs 4 voisins directs ne sont pas des espaces.

​

Exemple de carte invalide :

​

text
111111
1000 1
111111

Le 0 en position (4, 1) est adjacent à un espace, donc invalide.
5.5 - Vérifications finales

Vérifier qu'il n'y a pas de lignes vides au milieu de la carte. Retourner "Error\n" avec un message explicite si une validation échoue.
